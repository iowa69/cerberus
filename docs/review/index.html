How this review was run. Ten passes examined the codebase from ten different angles, each with its own lens and no knowledge of the others' conclusions. Findings were then checked against a running pipeline: miniature but real references (a minimap2 index, a bowtie2 index, a Kraken2 database and auxiliary FASTA, all built from synthetic genomes) let the whole tool execute end-to-end on reads whose origin is encoded in their names, so host removal could be measured rather than argued about. That step mattered — it corrected an early hypothesis about pair desynchronisation, and it confirmed the more serious finding underneath it.

The findings that mattered most

critical A long-read preset on paired input silently produced empty output

what
minimap2 only emits paired records under -x sr. With --platform ont (or any long-read preset) on -r1/-r2, no record carried a READ1 or READ2 flag, so samtools fastq -1/-2 wrote nothing.
confirmed by
Running it: both output files held 0 reads and the process exited 0 with no warning.
fixed in v0.2.0
Paired alignment forces a pair-capable preset and warns; a stage that consumes reads and emits none now raises a warning that reaches the run report.

critical The conservative and aggressive filters were the same filter

what
drop_strategy compiled to -f 12 for "both" and -f 4 for "either"; combined with -s /dev/null the two selected identical reads. --meta, documented as "retains microbial reads even at the cost of some residual host", was behaving exactly like the aggressive head.
confirmed by
Feeding 1000 read pairs with one host mate and one microbial mate through both paths and comparing outputs byte for byte. The microbial mates were being routed to /dev/null as singletons.
fixed in v0.2.0
Pair-level filtering uses a samtools filter expression (flag.unmap || flag.munmap) that can actually express the rule. On the same input, meta now keeps 500 half-host pairs and profiling drops all 500 — a difference that did not previously exist.

critical A dead process in a pipe reported success

what
pipe() checked only the last process's exit status. An OOM-killed minimap2 feeding a healthy samtools view produced a truncated BAM that passed samtools quickcheck.
confirmed by
Shimming an aligner to exit 137 mid-stream: 502 of 2000 records survived and the pipeline reported success.
fixed in v0.2.0
Every stage's status is checked and the failing stage is named in the error.

high The GDPR head's advertised third mechanism did not exist, and its first was tuned backwards

what
The manifest described human_kmer_set as a "belt-and-braces bbduk scrub, orthogonal to Kraken2", fetched it, and no code read it. Separately, Kraken2 ran at --confidence 0.5 against a database containing only host taxa — where a high threshold does not suppress false positives, it simply lets host reads escape as "unclassified". Two sequencing errors in a 150 bp read are enough; on ONT data at 2-5% error essentially nothing reached the threshold.
fixed in v0.2.0
The k-mer scrub is wired in as a real third mechanism; the default confidence is 0.05 and exposed as --gdpr-confidence; and the "zero detectable human reads" claim is replaced by measured, reported per-mechanism removal, because no reference-based filter can establish absence.

high --dry-run deleted the previous run's results, then crashed

what
final.unlink() sat outside the dry-run guard in every pipeline, so a dry run removed real outputs before failing with FileNotFoundError on a QC report it had never written.
fixed in v0.2.0
Publishing is atomic and never removes a file before its replacement exists; dry runs complete cleanly and still produce a report.

What was verified as sound

  • R1/R2 synchronisation held on every path traced, including the ones initially suspected of desynchronising — samtools' singleton routing was protecting them.
  • Concatenated gzip members read back as a single stream through every consumer tested, including pigz-produced members, so the merged-FASTQ design is sound.
  • Secondary and supplementary alignments cannot duplicate reads in the output.
  • The reference downloader hashes to a temporary file before renaming, so a corrupt download can never land at the final path.
  • The conda recipe's declared SHA256 matched the real v0.1.1 GitHub tarball.
  • The wheel builds correctly and ships the packaged reference manifest.
  • Zenodo helper scripts never log or persist the API token.
  • All mode-combination validation errors exited cleanly with code 2.

Outcome

All findings above are fixed in Cerberus v0.2.0, alongside 50 regression tests — one per defect, each documenting the wrong behaviour it prevents — and an end-to-end smoke test that builds miniature references and asserts host removal by read provenance rather than by exit code. Every run now writes reports/cerberus_report.html: resolved parameters, per-stage read accounting, verification of every output file, the per-mechanism GDPR breakdown, and any warnings raised.
