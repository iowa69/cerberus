## 1. noarch decision

**Use `noarch: python`. This is not a close call.**

The premise that architecture-specific *run* dependencies argue against `noarch` is backwards. `noarch` describes what is **inside** the package — here, pure Python bytecode and a console script, no compiled objects. Run dependencies are resolved **per-platform at install time**; a `noarch` package installed on osx-arm64 pulls the osx-arm64 build of `minimap2`. The two concerns are orthogonal.

Evidence, in order of weight:

**a. The package is already published as noarch and it works.** anaconda.org API for `bioconda/cerberus-mg` returns `latest_version: 0.1.1`, `files: [('0.1.1', 'noarch')]`. Dropping `noarch` now would move the package to a per-arch subdir — an unforced regression on a package that already ships fine.

**b. Bioconda's documentation states the rule with no carve-out.** From <https://bioconda.github.io/contributor/guidelines.html>: *"Recipes that contain pure Python packages should be marked as a 'noarch' package… add `noarch: python` to the `build` section."* Nothing conditions this on the nature of run dependencies.

**c. The linter enforces it.** `bioconda-utils` defines `should_be_noarch_python` — *"Pure Python packages without compiled modules should use `build: noarch: python`"*. The opposing check, `should_not_be_noarch_compiler`, fires only when the recipe **uses compilers**. This recipe has no `{{ compiler(...) }}` and no `build.sh`, so only the first check applies. Removing `noarch` trips it.

**d. The convention is overwhelming and current.** In the clone, 2665 recipes use `noarch: python`; of those, **614 also list a compiled bioinformatics tool in `run:`**. Real recipes, all `noarch: python`:

| Recipe (path under `recipes/`) | Compiled run deps |
| --- | --- |
| `humanfilt/meta.yaml` | bwa, samtools, minimap2, bowtie2, kraken2, trim-galore, bbmap, fastuniq, seqkit, pigz |
| `pathogen-profiler/meta.yaml` | bwa, minimap2 >=2.28, samtools >=1.12, bcftools, delly, gatk4, bedtools, freebayes, snpeff, trimmomatic, parallel |
| `metatrawl/meta.yaml` | sylph, samtools, bowtie2, prodigal, sra-tools, ncbi-datasets-cli |
| `bakta/meta.yaml` | pyrodigal, aragorn, infernal, diamond, blast |
| `checkm-genome/meta.yaml` | hmmer, prodigal, pplacer |
| `gottcha2/meta.yaml` | minimap2, samtools |

`humanfilt` is the closest analogue in the entire channel — a pure-Python host-read-removal CLI wrapping almost exactly our tool set — and it is `noarch: python`. `metatrawl` was merged three commits before HEAD (`246d02ae Update metatrawl to 0.2.4 (#67617)`), so this is live convention, not legacy.

**e. The apparent counterexamples aren't counterexamples.** `quast` and `medaka` are not `noarch` — but neither is pure Python. QUAST ships bundled C/C++ that is compiled at build time; medaka ships compiled extensions. They are excluded by "pure Python", not by their run deps.

**f. Dropping noarch makes CI *harder*, not easier.** A non-noarch recipe is built and tested separately on linux-64 **and** osx-64, so every run dep has to solve on osx-64 anyway — the exact risk the change was presumably meant to avoid. A `noarch` recipe is built and tested once. I verified the full run list solves on osx-64 (165 pkgs) and osx-arm64 (179 pkgs), so neither path is actually blocked, but noarch is strictly less CI surface.

**g. If a dep were ever missing on one platform, the fix is a selector, not abandoning noarch.** `checkm-genome/meta.yaml` demonstrates the idiom inside a `noarch: python` recipe:

```yaml
    - pplacer ==1.1.alpha20  # [not (osx and x86_64)]
    - pplacer >=1.1.alpha19  # [osx and x86_64]
```

## 5. Recommended run: list

All existing pins are satisfiable — every floor is cleared by the current build (note `kraken2 2.17.1 > 2.1.3` and `bbmap 40.00 > 39.0` compare correctly under conda's component-wise version ordering). The problem is not the pins, it is that **three dependencies are not used at all**.

Evidence from the code (`cerberus/`, excluding `build/`):

*Hard requirements* — `require_tools()` aborts the run if absent:

- `cerberus/orchestrator.py:36` — `_TOOLS_ALWAYS = ("minimap2", "samtools")`, needed by **every** run
- `:38` `qc_short → fastp`; `:39-40` `meta`/`profiling → bbduk.sh` (bbmap); `:41` `profiling_full → bowtie2`; `:42` `gdpr → kraken2`
- `:116` long mode requires `fastplong` **or** `chopper`
- `cerberus/stages/align.py:317` — `require_tools("winnowmap", "samtools")`, reachable from `pipelines/long_read.py:77` under `--double-pass`
- `cerberus/refs.py:467` — raises `RefManagerError("zstd not found, required to extract .tar.zst")`

*Soft* — invoked but with an explicit in-code fallback:

- `pigz` — `stages/concat.py:101-102`, `stages/qc.py:139`, `stages/kraken.py:205` all fall back to `gzip`
- `aria2c` — `refs.py:385-438`, falls back to urllib (`"aria2c not found; falling back to urllib (slower)"`)

*Not used by the installed package at all:*

- **`bedtools` — zero references in `cerberus/`.** Its only use is `scripts/build_refs/mask_t2t_hla.sh:66,71`, a reference-construction developer script. `pyproject.toml:40` sets `include = ["cerberus*"]`, so `scripts/` is **not installed**. The repo's own `environment.yml:26` even annotates it: *"only needed by scripts/build_refs/*, not by the pipeline itself"*.
- **`seqkit` — never invoked.** Two hits total: the `doctor` display list (`cli.py:336`) and a code comment (`stages/kraken.py:217`). Not in `environment.yml` either.
- **`multiqc` — never invoked.** One hit: the `doctor` display list (`cli.py:336`). Not in `environment.yml`.

`chopper` is the *alternative* to `fastplong` for long-read QC; shipping `fastplong` already satisfies `orchestrator.py:116`, so it is redundant.

Dropping those four cuts the closure from **206 to 124 packages on linux-64**. The 82 packages removed are almost entirely multiqc's tree — numpy, polars, plotly, pydantic, kaleido, networkx, nss, jinja2, and even `clang-22`/`libllvm22`/`compiler-rt`. That is the single biggest solve-fragility and install-size win available here, and an over-broad `run:` list is exactly the kind of thing reviewers push back on.

Recommended `run:` (13 entries):

```yaml

    - python >=3.10
    - tqdm >=4.66
    # required by every run
    - minimap2 >=2.28
    - samtools >=1.20
    # short-read QC, k-mer filtering, profiling, GDPR modes
    - fastp >=0.24
    - bbmap >=39.0
    - bowtie2 >=2.5
    - kraken2 >=2.1.3
    # long-read QC
    - fastplong >=0.2

    - winnowmap >=2.03
```

If you want it tighter still, `aria2` and `pigz` both have working fallbacks and could be dropped (−2 pkgs); I'd keep them, since reference download is a headline feature and they cost almost nothing. `chopper` may be re-added at zero real cost if you want both long-read QC backends available, but it is not required.
